# Ambiguity Checklist

Use this only after the core `SKILL.md` procedure.

## Missing input tests

- Artifact: What object is being acted on?
- Objective: What result does the user want?
- Scope: Is this a local change, global method, experiment, exploit, or analysis?
- Constraints: Are time, tools, environment, output format, or risk constraints material?
- Specialist fit: Would one specialist handle the unknown cheaply?

## Ask only when blocked

Ask a user question only if all are true:

- The answer changes the selected skill.
- The answer cannot be discovered from available context.
- A wrong assumption would waste meaningful work or create risk.

## Do not escalate to council just because

- Two domains are mentioned casually.
- The request is vague.
- The router lacks confidence.
- The user wants a simple first pass.

Use council only when multiple specialist interpretations must be reconciled.
